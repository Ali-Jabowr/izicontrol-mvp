## 3:50–4:30 — Где ошибается

*Экран: README, раздел «Где решение ошибается» (можно листать по пунктам).*

> Честно про слабые места.
>
> Первое: grounding проверяет, что цитата существует, но не то, что вывод из
> неё верен. Настоящая цитата при неверной интерпретации пройдёт проверку.
> Лечится LLM-судьёй — в двухчасовой MVP это не влезло.
>
> Второе: «следующий четверг» в русском языке принципиально неоднозначен —
> ближайший или через неделю. Резолвер берёт одну трактовку и всегда вешает
> флаг.
>
> Третье: ошибки менеджера — оценочная категория: что считать ошибкой, задано
> списком в промпте, то есть мной, а не методологией заказчика. И пустой
> список двусмыслен — чистая работа это или пропуск модели. Система честно
> это помечает.

## Опциональная вставка: живой тест на подделку (+25–30 секунд)

Вместо одного из пунктов блока «Где ошибается» (укоротите его до двух).
Показывает, что отчёт не верит JSON на слово — валидаторы перечитывают
цитаты по транскриптам при каждой сборке отчёта.

**Подготовить до записи:**

```bash
python - <<'PY'
import json
d = json.load(open('out/analysis.json'))
d[0]['risks'][0]['evidence'][0]['quote'] = 'выдуманная цитата, которой нет в транскрипте'
json.dump(d, open('out/analysis_broken.json', 'w'), ensure_ascii=False, indent=2)
PY
```

**В кадре:**

```bash
python -m callscope report --source out/analysis_broken.json -o out_broken
xdg-open out_broken/report.html   # показать красный ✗ у подменённой цитаты
```

**Текст:**

> И ещё один живой тест. В сохранённом JSON подменяю одну цитату на
> несуществующую и пересобираю отчёт — валидаторы перечитывают цитаты по
> транскриптам заново. Подделка встаёт красным крестом: отчёт не верит
> сохранённому JSON на слово.
