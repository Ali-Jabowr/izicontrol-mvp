# callscope — разбор клиентских звонков

MVP по тестовому заданию: из транскрипта звонка получить структурированный разбор —
итог, следующий согласованный шаг, дату следующего действия, потребности клиента,
риски, ошибки менеджера и то, что требует внимания руководителя.

Ключевое требование ТЗ — «не придумывайте отсутствующие факты, а неоднозначность
должна быть явно видна» — вынесено в архитектуру, а не в формулировку промпта.

---

## Быстрый старт

```bash
uv venv && uv pip install pydantic pyyaml

# полный прогон: 4 транскрипта → JSON + HTML + CSV
# (нужна локальная папка transcripts/ — материалы задания не публикуются)
python -m callscope run transcripts -o out

# пересобрать отчёт из сохранённого JSON, без обращения к LLM и без ключей
python -m callscope report --source out/analysis.json

# сверка с ручным эталоном
python -m callscope eval
```

Готовый `out/analysis.json` лежит в репозитории, поэтому `report` и `eval`
запускаются у проверяющего без каких-либо ключей и доступов.

запускаются у проверяющего без каких-либо ключей и доступов.

Открыть отчёт: `xdg-open out/report.html`

## Архитектура

Одна мысль, на которой держится всё решение:
**LLM извлекает смысл — детерминированный код проверяет факты.**

```
transcripts/*.md
   │
   ├─ ingest.py ──────── шапка разбирается регулярками:
   │                     дата, день недели, компания, участники.
   │                     День недели считается по календарю Python,
   │                     а не берётся из текста.
   │
   ├─ prompt.py ──────── в промпт кладётся ГОТОВЫЙ КАЛЕНДАРЬ на ±3/+21 день.
   │                     Модель не считает даты, она выбирает из списка.
   │
   ├─ providers.py ───── один вызов LLM на транскрипт, 4 транскрипта параллельно.
   │                     Провайдер за интерфейсом: claude-cli | openai-compat.
   │
   ├─ models.py ──────── Pydantic-схема. Каждое утверждение обязано нести
   │                     массив evidence с дословными цитатами.
   │
   ├─ validate.py ────── пять детерминированных проверок (ниже)
   │
   └─ render.py ──────── самодостаточный HTML + CSV + канонический JSON
```

### Пять проверок поверх выдачи модели

| # | Проверка | Что ловит |
|---|----------|-----------|
| 1 | **grounding** | каждая цитата ищется в исходном тексте после нормализации (регистр, `ё/е`, кавычки, тире). Пункт без единой подтверждённой цитаты помечается «НЕ ПОДТВЕРЖДЕНО» и краснеет в отчёте |
| 2 | **резолвер дат** | дата пересчитывается независимо из выражения («к понедельнику», «после двадцатого») и якорной даты. Расхождение с моделью — видимый флаг, побеждает резолвер |
| 3 | **день недели** | если в тексте «пятница», а дата выпала на четверг — конфликт наверх |
| 4 | **дата в прошлом** | действие раньше дня звонка = почти всегда ошибка года |
| 5 | **полнота** | пустое обязательное поле превращается в честную запись `data_gaps` с причиной, а не в выдуманный текст |

### Почему такое разделение

Модель хорошо понимает деловой русский и плохо считает календарь — а цена ошибки
в дате выше, чем в формулировке риска: сорванная встреча. Поэтому арифметика
вынесена из модели целиком, а её предложение используется только как гипотеза,
которую проверяет код.

Grounding-валидатор — около двадцати строк, но он делает выдумывание бессмысленным:
неточная цитата механически не находится в исходнике, и пункт уезжает в красное.

### Модель различает три вещи, которые обычно сливаются в одну

- **Согласованный шаг** — стороны договорились (`agreed: true`)
- **Отклонённое предложение** — менеджер предложил, клиент не подтвердил (`agreed: false`).
  В транскрипте 3 менеджер просит записи «завтра», клиент прямо отказывает —
  записать это как договорённость было бы галлюцинацией
- **Ограничение** — «я недоступна в пятницу после четырёх», «не звоните в магазины
  без меня». Это не действие и в план работ попадать не должно

### Про выбор провайдера

Клиент в транскрипте 3 говорит прямым текстом: *«если для анализа вы отправляете
записи в зарубежное облако, проект сразу стоп. Нужен российский контур»*.

Это продуктовое требование, а не деталь реализации, поэтому движок спрятан за
интерфейсом `LLMProvider.complete(system, user) -> str`. Демо работает на headless
Claude CLI; адаптер `OpenAICompatProvider` подключает любой OpenAI-совместимый
endpoint — GigaChat, YandexGPT или локальный vLLM — сменой `base_url`, без
изменений в пайплайне. Промпт и валидаторы от провайдера не зависят.

## Что было проверено

### Автоматическая сверка с эталоном

`gold/gold.yaml` размечен вручную по ловушкам, которые заложены в транскрипты.
Проверяются не формулировки модели (они каждый раз разные), а факты: даты, год,
точность, попадание отклонённого предложения в согласованные шаги и покрытие
ключевых рисков и ошибок менеджера.

Что именно ловится в каждом звонке:

| Транскрипт | Ловушка | Результат |
|---|---|---|
| Альфа-Металл | «в этот четверг» + уточнение «10 сентября в 15:00 **по Екатеринбургу**» | дата и часовой пояс сохранены |
| Альфа-Металл | две датированные задачи в одном звонке, не одна | обе в `all_dates` |
| Зелёная Полка | «к понедельнику» от вторника — арифметика по дню недели | 14 сентября |
| Зелёная Полка | «в пятницу после четырёх я недоступна» — это **ограничение**, а не задача | в `constraints`, не в `next_steps` |
| СтройКомплект | клиент **исправил** время: «после 11:00» → «лучше в 11:30» | 11:30 |
| СтройКомплект | менеджер предложил записи «завтра», клиент отказал | шаг помечен `agreed: false` |
| Север-Транс | «после двадцатого» про январь при разговоре в сентябре 2026 | **2027**-01-21, не 2026 |
| Север-Транс | «в декабре пришлите сравнение» — месяц без числа | `precision: month_only`, дата не выдумана |

Отдельно стоит отметить последний случай: в тексте сказано просто «после двадцатого
числа», без месяца. Резолвер такое выражение сам не берёт — он достраивает месяц
из ответа модели, но **арифметику дня пересчитывает сам**, и расхождение пометил бы флагом.



Помимо автоматической сверки:

- **Юнит-тесты резолвера дат** — 15 проверок: 12 выражений из реальных
  транскриптов (`в этот четверг`, `к понедельнику`, `после двадцатого числа
  января`, `два-три рабочих дня`, `в декабре`) плюс 3 негативные регрессии
  («5 машин» — не май, «средства» — не среда): 15/15.
- **Негативный тест на галлюцинации** — в сохранённом JSON цитата подменяется на
  несуществующую; пункт обязан получить пометку «НЕ ПОДТВЕРЖДЕНО» и красную рамку,
  а не попасть в отчёт как факт. Воспроизводится без ключей: `python -m callscope
  selftest` (раздел 3 — повторная валидация на временном транскрипте). Локально,
  при наличии папки `transcripts/`: правьте цитату в `out/analysis.json` и запустите
  `python -m callscope report` — валидаторы перечитают цитаты по исходнику.
- **Проверка на устойчивость схемы** — ответ модели валидируется Pydantic;
  падение одного транскрипта не рушит пакет, остальные три доходят до отчёта.

## Где решение ошибается

Честный список, а не дисклеймер.

1. **Резолвер дат покрывает только деловые конструкции.** Разобраны: явные даты,
   `сегодня/завтра/послезавтра`, дни недели, `после N-го`, `N рабочих дней`,
   месяц без числа. Всё остальное — `relative_unresolved` и флаг «проверить вручную».
   Это осознанный выбор: лучше честно не знать, чем уверенно ошибиться.
2. **`«следующий четверг»` принципиально неоднозначен** в русском языке
   (ближайший или через неделю — зависит от говорящего). Резолвер берёт
   «+1 неделя» и **всегда вешает флаг неоднозначности**. Автоматически это не решается.
3. **Grounding проверяет цитату, а не вывод из неё.** Если модель приложит реальную
   цитату к неверной интерпретации, проверка пройдёт. Ловится только LLM-судьёй
   или человеком — в MVP не делалось.
4. **Пустой список ошибок менеджера двусмыслен** — это либо чистая работа, либо
   пропуск модели. Система не различает и честно вешает флаг «проверить вручную».
5. **Ошибки менеджера — оценочная категория.** Что считать ошибкой, задаётся
   списком в промпте, то есть моей гипотезой о продажах, а не методологией
   заказчика. Прогон на одном и том же транскрипте может дать 2 или 4 пункта.
6. **Один прогон — одна выборка.** Температура 0 стабилизирует, но не гарантирует
   идентичность. Для продакшена нужны n-прогонов и согласие между ними.
7. **Часовой пояс распознаётся, но не нормализуется.** «15:00 по Екатеринбургу»
   сохраняется как есть и выделяется в отчёте; перевода в МСК нет.
8. **Транскрипт считается чистым.** Реальная расшифровка звонка содержит ошибки
   ASR, перебивания и неразделённых спикеров — на таком входе качество упадёт,
   и это не проверялось.

## Что сделал бы следующей итерацией

**По качеству разбора**
1. **LLM-as-judge поверх grounding** — проверять не только наличие цитаты, но и то,
   что вывод из неё следует. Закрывает пункт 3 выше.
2. **Self-consistency** — три прогона с разными seed, в отчёт идёт пересечение;
   расхождения показываются как зона неуверенности.
3. **Расширить gold-набор** до 30-50 размеченных звонков и считать precision/recall
   по каждому полю отдельно. Сейчас 4 звонка — это проверка на ловушки, а не метрика.

**По продукту** (следует из самих транскриптов)
4. **Утренний дайджест руководителя.** Олег из транскрипта 3 формулирует продукт
   буквально: *«не хочу слушать всё сам; хочу утром видеть пять разговоров, куда
   мне надо вмешаться»*. Ранжирование звонков по риску + топ-5 в почту — это
   следующая функция, и она уже почти собрана: `needs_supervisor_attention`
   и флаги валидации дают сигнал для скоринга.
5. **Дедлайны в календарь и CRM.** Каждый `next_step` с `resolved` датой — это
   готовая задача. Отдельно — контроль просрочки: шаг обещан на 14 сентября,
   а в CRM ничего не произошло.
6. **Тренды по менеджеру.** Ошибки уже типизированы; накопив их, можно показать
   руководителю, что Дарья систематически даёт скидку на неценовое возражение, —
   это материал для обучения, а не для разбора одного звонка.

**По инженерии**
7. **Российский контур** — подключить GigaChat/YandexGPT через существующий
   `OpenAICompatProvider` и сравнить качество с текущим движком на том же gold-наборе.
   Без этого сделка из транскрипта 3 не двигается.
8. **Вход из аудио** — Whisper + диаризация, чтобы принимать записи звонков,
   а не готовые транскрипты.
9. **Очередь и идемпотентность** — сейчас это CLI на 4 файла; для потока звонков
   нужна очередь, ретраи и кэш по хэшу транскрипта.

## Состав репозитория

```
callscope/
  ingest.py      разбор шапки, якорная дата, календарь
  prompt.py      системный промпт и сборка сообщения
  providers.py   claude-cli | openai-compat за одним интерфейсом
  models.py      Pydantic-схема результата
  dates.py       резолвер русских относительных дат
  validate.py    пять детерминированных проверок
  evaluate.py    сверка с эталоном
  render.py      HTML + CSV
gold/gold.yaml   ручной эталон по ловушкам в транскриптах
out/             analysis.json, report.html, report.csv
```

Ограничение по времени — 2 часа, поэтому сознательно не делалось: веб-интерфейс
с сервером, база данных, аутентификация, приём аудио, дообучение модели.
